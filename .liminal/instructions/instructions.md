# Instructions

- Every change to `AGENTS.md` or `.liminal/instructions/` needs the user's approval. Show the exact text and wait. A direct request from the user to make that change is the approval.
- Write only what a check cannot enforce. A checked rule that agents often break may get a one-line note under "Checked".
- When a rule becomes checkable, add the check and delete the rule.
- One file per area, split by code boundary or kind of work. Give each file a `read-when:` line in its front matter, and list it in the `AGENTS.md` instructions table with the same text.
- One rule per bullet, imperative, plain words. State the rule, not its history.
- Each rule lives in one file. Search for an existing home before adding one.
- `AGENTS.md` holds only rules that apply to all work.
